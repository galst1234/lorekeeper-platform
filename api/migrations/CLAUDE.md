# Migrations

## Creating migrations

Do NOT create migration files manually. Always use alembic to autogenerate them:

```bash
alembic revision --autogenerate -m "description"
```

## Editing migrations

Only edit a generated migration file in these two cases:

**Data migrations** — when you need to backfill or transform existing rows, add a `op.execute()` call or a Python data-migration step inside the migration.

**Multi-step non-null column additions** — when adding a column that must be `NOT NULL` without a server default:
1. Add the column as `nullable=True`
2. Backfill all existing rows
3. Alter the column to `nullable=False`

These three steps must be in a single migration file (or split across ordered migration files if downtime is a concern).

For all other schema changes (adding a nullable column, adding an index, renaming, dropping, etc.) the autogenerated output should be used as-is.
